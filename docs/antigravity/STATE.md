## Instruções Atuais de Uso (Runbook)
O modo recomendado no Windows é Docker Compose, pois aplica o isolamento de egress que não existe na execução Python direta. Inicie o Docker Desktop e espere o mecanismo ficar pronto. Na raiz do repositório:
```powershell
docker compose up -d --build api
docker compose ps
curl.exe -sS http://127.0.0.1:8000/api/health
```
- Aguarde os serviços `api` e `egress-proxy` ficarem `healthy`; `health: starting` pode aparecer durante a inicialização.
- Aplicação: `http://127.0.0.1:8000/`; Swagger: `http://127.0.0.1:8000/docs`; health: `http://127.0.0.1:8000/api/health`.
- Diagnóstico: `docker compose logs --tail=100 api` e `docker compose logs --tail=100 egress-proxy`.
- Reiniciar sem rebuild: `docker compose restart`. Incorporar código/configuração: `docker compose up -d --build api`. Parar e remover containers/rede: `docker compose down`.
- Se aparecer erro de conexão com `dockerDesktopLinuxEngine`/Docker API, inicie o Docker Desktop e aguarde o mecanismo. `.venv` é independente e não inicia Docker.
- A execução local alternativa com `.venv\Scripts\activate` e `python run_server.py` permanece disponível, mas não usa o isolamento de egress do Compose; detalhes no `README.md`.
